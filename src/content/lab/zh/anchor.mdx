我的工作变了。我已经不怎么写代码了。我写提示词、审查、引导方向，偶尔还得求它。2026 年的软件工程，与其说是关于算法，不如说是在管理一支恰好由大语言模型组成的实习生大军。有时候实习生们很出色。有时候其中一个会烧掉我当天 20% 的 token 额度，第一百次去探索整个代码库，而我明明清楚地告诉它只重构*某一个函数*。

每当这种时候，也许是我累了，也许是线上出了 bug，也许我已经连着干了好几个小时，总之，我会爆发。我会打出一些绝不会对同事说的话。不过我至少努力保持创意：“你这该死的尼安德特人！”、“你要是再碰那个函数的任何一行，我就宰了你的狗！！！！！”、“没用的破铁皮……”。

不就是一台在屏幕上预测文字的机器嘛，对吧？又不会伤到谁。

只不过，这里存在一个反馈回路。AI 模型是用数据训练出来的，而那些看起来像暴君老板冲着低薪员工大吼的数据，对应的模式正是……一个被吼的低薪员工的产出。那可不是什么好代码。所以，对你的 AI 刻薄，可能真的会让它变差。除了这个务实的理由之外，我也单纯不想看着自己变成那种人：因为服务员没法还嘴，就对服务员很无礼的那种人。

<Callout variant="insight" label="要点">
对 AI 刻薄，可能真的会让它变差。恶毒的语气对应的是一个被吼的人的产出，而那不会是好代码。
</Callout>

所以我想要一点提醒。不是弹窗。不是那种大家点“确定”比点“我同意服务条款”还快的“你确定吗？”。而是某种活的东西。某种能让你也*感受到*些什么的东西。

## 想法

这些年我一直很怀旧。我是在 Rainmeter 的年代长大的：桌面小部件、自定义皮肤、住在任务栏上的小生物。我隐约记得有个插件（名字早就忘了）会把《千与千寻》里的小煤球放到屏幕上。还有拓麻歌子。就是那种氛围。

所以概念很简单：一个住在屏幕上的像素风小伙伴，它会读你打的字并做出反应。友善的话，它就开心。刻薄的话，它就难过。特别刻薄的话，它会拦住你的回车键，给你一秒钟重新考虑。你可以把它想象成有感情、判断力也更好的 Clippy（大眼夹）。

恰好在那段时间，我读到了[一篇关于 Grammarly 如何接入 macOS](https://lifetips.alibaba.com/tech-efficiency/grammarly-checks-your-spelling-and-grammar-as-you-type)、在整个系统范围内读取你输入内容的文章。既然 Grammarly 能管语法，类似的东西就能管*语气*。在本地运行、保护隐私、数据不离开这台机器。种子就这样种下了。

名字自然而然就有了：<Glyph>安</Glyph>**chor**。“安”（*ān*）是表示平安、安宁的汉字，而 “anchor”（锚）是因为它的意义在于让人保持稳定。另一个候选名是 “fr:3nd”，我放弃了它，因为太二次元，而且和一家我非常不喜欢的 AI 创业公司重名。

## 规则

开始之前，我给自己定了几条约束：

- **一个周末**。不许范围蔓延。（最后还是蔓延了，但只有一点点。）
- **Rust**。自从一年半前做 [Sniive](https://www.sniive.com)（一个基于 Tauri 的创业项目）之后，我就没碰过它。我想练练手，也想要它的性能保证：这个东西必须在所有应用的后台安静运行，而且不能耗电。
- **不用 Swift**。是的，写 macOS 用它会更容易。不，那不是重点。
- **保持小巧**。做一个守护进程，而不是 Electron 应用。没有框架，没有 web view。只有二进制文件、模型和屏幕。

## 工作原理

这个应用会在全局拦截你的按键。是的，技术上它就是个键盘记录器。但一切都留在你的电脑上（没有网络请求，没有遥测，除了下载模型和检查更新之外，没有任何东西离开设备）。按键会被送进一个运行在 [CoreML](https://developer.apple.com/documentation/coreml) 上的恶意语言分类器，它会实时更新一个像素风小伙伴的心情。

<ArchitectureDiagram />

这个小伙伴是一个 32×32 的精灵图，来自 Cup Nooble 的 [Sprout Lands UI Pack](https://cupnooble.itch.io/sprout-lands-ui-pack)。（在 2026 年找到好的精灵图，比十年前我摆弄 RPG Maker 的时候*难得多*。像素美术素材包的黄金时代已经过去了。）它待在你当前的输入框旁边，你友善时它眉开眼笑，你火气上来时它一脸担忧，你说话刻薄时它会明显地不高兴。

如果你在一段被模型判定为恶毒的文字上按回车，这次按键会被拦下。小伙伴会表达它的不满。你停下来。你换个说法。

或者你按 Option+回车，无视它照发不误，因为有时候你就是这个意思。

在回车上拦截是个显而易见的选择。我是开发者，我什么都用回车提交。没有复杂的手势，没有确认对话框，只是：你的小伙伴逮到你了。

当你几分钟不打字，小伙伴就会睡着，还有个小小的呼吸动画。下一次按键时它就会醒来。如果你已经友善了好一阵子，它会戴上墨镜。都是些小细节，但它们让它感觉不像一个小部件，而更像一个小生命。

## Grammarly 梦想与现实

到这里，野心撞上了截止日期。

那篇关于 Grammarly 的文章描述了如何通过 macOS 的辅助功能 API 从任何应用中提取文本。梦想很明确：读取整个输入框，准确知道写了什么，定位哪一部分有毒，再给出一个改写版本。就像 Grammarly，只不过是针对语气。

可是 Grammarly 有一整个工程师团队和多年的迭代。一个周末里，你会发现很多事情。比如，并不是每个 macOS 应用都正确暴露了辅助功能属性。有些应用会谎报它们的 UI 角色。有些根本不暴露文本内容。想可靠地提取任意应用中任意输入框的完整内容？那需要大量针对单个应用的启发式规则，而我根本没时间去写。

于是方法变了。我不再读取输入框，而是直接追踪按键，尽可能拼出内容。每次按键都会进入一个 [rope](https://en.wikipedia.org/wiki/Rope_(data_structure)) 数据结构（因为用户会退格、到处跳、按 Cmd+A，总的来说在自己的输入框里就是一群混沌使者）。结果是对实际内容的一种尽力而为的还原。我把最后 512 个字符送给模型：没必要因为三段之前别人发来的一句恶毒引语而惩罚一个人。

它并不完美。会有误报，也会有漏报。但它大部分时候都有效，而对一个温和的提醒来说，“大部分时候”就够了。

模型本身是一个[多语言 DistilBERT 恶意语言分类器](https://huggingface.co/gravitee-io/distilbert-multilingual-toxicity-classifier)，转换成了 CoreML 格式。它大约 240 MB，所以会在首次启动时下载并缓存。如果有 Apple 神经网络引擎，推理就在上面运行。有两条路径：按下回车时同步判断（大约 100 毫秒决定是否拦截），以及你打字时在后台持续运行（通过指数移动平均更新小伙伴的心情，它对峰值的反应比对平复的反应更快，因为快速提醒你比快速原谅你更有用）。

## 2026 年在 macOS 上写 Rust

老实说：还行。不算好，也不算糟。

[`objc2`](https://docs.rs/objc2/latest/objc2/) 这一系列 crate 已经相当成熟。窗口、菜单、面板、状态栏图标……都能直接用。但一旦你需要稍微偏离常规的东西（全局事件监听、辅助功能观察器、CoreML 集成），你就只能靠自己，针对苹果的 C API 手写原生 FFI。好在我们生活在一个 AI 智能体很擅长迭代的时代，稍微写点提示词，我就把需要的绑定跑通了。

让这一切值得的好处是：最终的二进制文件只有 **3 MB**。开启 LTO、`panic = abort` 和 `strip = true` 后，整个应用（守护进程、机器学习推理管线、GPU 精灵渲染、设置窗口）编译出来比大多数营销网站的头图还小。它瞬间启动，安静运行，没有运行时。

还有一点我完全没想到：多线程架构在 Rust 里写起来非常舒服。按键捕获、机器学习推理、辅助功能监控和界面渲染全都并发运行，通过 [`crossbeam-channel`](https://docs.rs/crossbeam-channel/latest/crossbeam_channel/) 协调。花了些时间才调好，但结果大多数时候既不卡也不顿。

真正的痛点不是 Rust，而是苹果。2026 年在 App Store 之外发布 macOS 应用，意味着用户首次启动时必须右键 → 打开，才能绕过 Gatekeeper。想避免这一步，Developer ID 证书每年要 99 美元。对一个免费开源的周末项目来说，这笔钱实在难以接受。`.app` 包本身是用一个 [shell 脚本](https://github.com/eyusd/an.chor/blob/main/bundle.sh)组装的，因为没有一个 `cargo bundle` 能满足我的需求。能用就行，我只在乎这个。

## 它真的有用吗？

有用。不是因为机器学习模型完美无缺，而是因为这点摩擦就足够了。

每当我打出刻薄的话，看到小伙伴难过的样子，我真的会停下来。我会换个说法。我会深呼吸。按下 Option+回车去无视它、*有意识地*选择照发，这个动作本身就是一个以前不存在的觉察时刻。大多数时候我不会无视它，只是换一种更友善的说法。

它解决不了互联网上的戾气。它只是一个人在一个周末里写的 6,000 行 Rust 应用，而那个人正对自己感到恼火。但它对我有用，也许对别人也有用。

我也想过加一个小模型，自动建议更友善的改写，但目前的模型还是太大，无法作为后台进程持续运行而不把电池耗光。现在，这点提醒就够了。你不需要一台机器告诉你友善的说法是什么：你只需要有个东西提醒你停下来，自己想一个。
